# Кнопка на сайте

Рендер идёт целиком в браузере: сервер, ключи и загрузка картинок никуда не
нужны. На страницу кладутся три файла из `src/` и вызывается одна функция.

## Минимально

```html
<button id="overlay">Картинка для соцсетей</button>

<script type="module">
  import { downloadComposite } from '/js/overlay/overlay.js';

  document.getElementById('overlay').addEventListener('click', async () => {
    const [track, stats] = await Promise.all([
      fetch(`/api/track/${runId}`).then((r) => r.json()),
      fetch(`/api/stats/${runId}`).then((r) => r.json()),
    ]);
    await downloadComposite({ photo: photoUrl, track, stats });
  });
</script>
```

`photo` — это `<img>`, `<canvas>`, `Blob` из `<input type="file">` или адрес
картинки. Размер результата берётся у фотографии.

## Прозрачный PNG — не для телефона

Соблазнительно отдавать прозрачный PNG и накладывать его в приложении. На
практике этот путь ломается, и ломается незаметно:

- телефон и мессенджеры охотно пережимают PNG в JPEG, а у JPEG альфы нет
  вовсе — прозрачное становится чёрным или белым;
- просмотрщики рисуют прозрачность **шахматкой**. Если человек не сохранил
  файл, а снял экран или потянул превью, шахматка запекается в картинку и
  уезжает в ленту вместе с цифрами.

Поэтому кнопка по умолчанию отдаёт `downloadComposite` — фотографию с уже
наложенным оверлеем. Накладывать нечего, терять нечего.

`downloadOverlay` остаётся для тех, кто собирает картинку в настоящем
редакторе: туда PNG доходит целым.

`src/overlay.js` тянет за собой `src/track.js` и `src/icons.js` — все три
файла должны лежать рядом. Сборщик не нужен, это обычные модули.

## Что отдаёт каждая функция

| | |
|---|---|
| `downloadComposite(data, options, filename)` | фотография с оверлеем, файлом — то, что вешается на кнопку |
| `renderComposite(data, options)` | она же `Blob`: если картинку надо отправить на сервер или показать в `<img>` |
| `downloadOverlay(data, options, filename)` | прозрачный PNG файлом |
| `renderOverlay(data, options)` | прозрачный PNG как `Blob` |
| `renderToCanvas(data, options, canvas)` | рисует на вашей канве: для живого предпросмотра |
| `DEFAULTS` | раскладка по умолчанию, от неё удобно отталкиваться |

`data` — это `{ track, stats }` и, для готовой картинки, ещё `photo`.
`options` — раскладка. Разделены нарочно: в первом то, что меняется с каждым
забегом, во втором то, что подобрано один раз и живёт в коде кнопки.

У `renderComposite` есть свои `format` (`image/jpeg` по умолчанию, можно
`image/png`) и `quality`.

## Раскладка

```js
{
  width: 1080, height: 1080,       // размер PNG; 'auto' по высоте — вплотную к цифрам
  color: '#1b3a93', accent: '#ff2d20',
  fontFamily: 'Montserrat', loadFont: true,
  stats: { x: 0.06, y: 0.08, scale: 0.1, gap: 1.32 },
  track: { show: true, x: 0.34, y: 0.3, size: 0.62, rotate: 0, accent: true, weight: 0.009, opacity: 1 },

  mode: null,                      // 'stats' | 'intervals'; пусто — выбирается само
  intervals: { x: 0.06, y: 0.04, scale: 0.055, colGap: 0.045, rowGap: 0.38,
               headGap: 1.5, labelMax: 0.24, ink: '#111111' },
  logo: { show: false, x: 1, y: 0, size: 0.16, opacity: 1 },
}
```

`mode` решает, что рисовать. Оставьте пустым — и модуль выберет сам: есть
разбор интервалов, значит рисуются они; нет — общие цифры. Переключатель на
странице подбора делает ровно это.

`logo` ставит знак S10. Его `x` и `y` — доли не от всей картинки, а от
свободного хода **внутри безопасной зоны соцсетей**: 0 прижимает к её краю,
1 — к противоположному. Поэтому знак не уедет под аватар сверху или под поле
ответа снизу, куда его ни двигай. Сама зона задаётся в `SAFE` (`src/logo.js`)
и при нужде передаётся своя: `logo: { safe: { top: 0.1, right: 0.05, bottom: 0.1, left: 0.05 } }`.

`track.rotate` — поворот маршрута в градусах по часовой стрелке. Север сверху
только потому, что так его отдаёт прибор; на фотографии важнее, чтобы контур
лёг в свободное место. Поворот считается до подгонки под рамку, поэтому
повёрнутый маршрут занимает её так же плотно, как и неповёрнутый.

Все координаты и размеры — доли ширины картинки, не пиксели. Поэтому одна и
та же раскладка одинаково ложится и на 1080×1080 для ленты, и на 1440×1800
для сторис.

Подбирать руками не нужно: откройте `npm run demo`, загрузите свой забег и
фотографию, подвигайте ползунки и скопируйте готовый объект.

## Размер под фотографию

`renderComposite` берёт размер у самой фотографии, задавать ничего не нужно.

Если всё же нужен отдельный прозрачный PNG под конкретный снимок, задайте ему
размер снимка — тогда в редакторе он встанет на место в масштабе 100%, и ни
одна линия не размоется пересчётом:

```js
await downloadOverlay({ track, stats }, { width: photo.naturalWidth, height: photo.naturalHeight });
```

## Чужой домен у фотографии

Если снимок лежит на другом домене, тот должен отдавать его с
`Access-Control-Allow-Origin` — иначе канва считается «запачканной» и
браузер откажется отдавать картинку. Модуль просит снимок с
`crossOrigin = 'anonymous'`, так что со своего домена всё работает само.

## Шрифт

Цифры набраны Montserrat. Если на сайте его нет, модуль подтянет его сам с
Google Fonts — за это отвечает `loadFont: true`.

Свой шрифт задаётся через `fontFamily`, и тогда загрузить его — забота
сайта: нужны начертания **800** (цифры) и **600** (подписи). Ширину строки
канва меряет тем шрифтом, который загружен в эту секунду, поэтому модуль
ждёт шрифт до первого измерения. Если сеть его не отдала, картинка всё
равно соберётся — просто системным шрифтом.

## Поддержка браузеров

Нужны `Path2D`, `canvas.toBlob` и `document.fonts` — это все браузеры с 2018
года. Ничего сверх этого модуль не использует: ни зависимостей, ни сборки,
ни сети (кроме шрифта).
